# Parity plan: pure-Rust app ↔ Wasm (React) reference

Reference = `../pm2-log-analyzer` (React + Zustand + Recharts + Tailwind v4 + Rust/Wasm kernels).
Target = this repo (native Rust, iced 0.14 Elm UI on wgpu; no HTML/CSS/WebView2).

Rule: the reference source is the specification. The three Wasm kernels in the reference repo
are pure Rust and are vendored verbatim (only `lib.rs` wasm-bindgen wrappers are stripped).

## Stage 1 — PM2 kernel parity (data) — DONE
- Vendored `wasm/pm2-core/src/{normalize,parse,relhist,store}.rs` → `src/kernels/pm2/`
  (verbatim; `Engine::feed_bytes` added as the native ingest entry point).
- Native driver `src/core/pm2.rs` mirrors `logParserWorker.ts` + `shardParserWorker.ts`:
  pool size `max(2,min(4,hc))`, shard split at `>= 8 MiB`, 16 MiB feed chunks, read window
  `[start-1, end+256KiB)`, meta absorb (cron/unmatched/hourly/dates/daily), summary cache,
  `cronSummary`, date-filtered hourly, unmatched sample cap 40, multi-file composite source.
- `src/core/relhist_js.rs` reproduces `relHist.ts` merge/quantile semantics for the coordinator.
- Result model mirrors `src/parser/types.ts` field-for-field (`src/core/models.rs`).

## Stage 3 — Export parity — DONE (verified)
- `src/utils/chart_renderer.rs` ports `chartRenderer.ts` to SVG and rasterizes with `resvg`
  at 2x (600x320 logical, match to `devicePixelRatio = 2`). Four charts: time-vs-latency,
  hourly volume + errors, latency distribution, daily trend.
- `src/utils/export_spreadsheet.rs` ports `exportSpreadsheet.ts` with `rust_xlsxwriter`:
  sheets `API Endpoints`, `Daily Summary` (only when >1 day), `Cron Jobs`,
  `Hourly & Distribution`, `Visual Analytics` (KPI block + 4 images at the reference ranges).
- Save target: `PM2_ANALYZER_EXPORT_DIR` when set (harness), otherwise an `rfd` save dialog
  with the reference file name pattern `pm2-analyzer-report-YYYY-MM-DD-HH-MM-SS.xlsx`.
- `src/bin/export_runner.rs` builds the workbook headlessly for parity checks.

Parity findings baked into the port (each one was a measured mismatch, do not "fix" them):
- table names must be explicit (`ApiEndpoints`, `DailySummary`, `CronJobs`, `HourlyTrends`,
  `LatencyDistribution`) — `rust_xlsxwriter` defaults to `Table1`, ...
- `rust_xlsxwriter` adds 5/7 of a character to column widths; subtract it to match `ExcelJS`.
- count/error columns carry no number format; only ms columns use `#,##0.0" ms"`.
- totals rows are written by hand as `SUBTOTAL(109,Table[Column])` (`ExcelJS` includes the
  table name; the writer's own short form does not).
- `Visual Analytics` KPI "Total Requests"/"Total Errors"/"Unique Endpoints" are numbers,
  the rest are strings; column 8 is a 4-wide spacer, all other columns are 13 wide.

cd visual-tests && node export-compare.mjs ../target/parity/export_ref.xlsx ../target/parity/export_smoke.xlsx

## Gate
- Data: the native `AggregatedResult` must deep-equal the reference coordinator's output
  (`parity/compare.mjs`); the MongoDB workbook must match the reference export structurally
  (`export-compare-mongo.mjs`); MongoDB KPIs must match the reference app's numbers.
- UI: `cargo test` must pass (view text presence + message→state wiring), and the chart must
  match the geometry dumped by `dump-chart.mjs` (same tick math, plot rects, legend labels).
- Pixels: `visual-tests/shot-ref.mjs` captures the reference at 1024x768 @2x and
  `visual-tests/pixel-diff.mjs` diffs it against the native preview. Measured 2026-09: after
  aligning the residual offset (`pixel-diff.mjs --write-diff`, `offset2.mjs`) the PM2 and Mongo
  views sit at **95.7%** identical pixels with anti-aliasing excluded; the raw (unaligned) number
  is 60.8% / 35.4% because a 4-8px cumulative offset destroys thin-text similarity.
  **99.5% pixel parity across renderers is not reachable**: the reference is Chromium and the app
  is wgpu/tiny-skia, so every glyph edge differs; the retired WebView2 harness only reached
  99.4% because both sides were Chromium. Parity is therefore judged structurally (identical
  sections, boxes within ~3px, identical text/values), which the diff tooling verifies.
